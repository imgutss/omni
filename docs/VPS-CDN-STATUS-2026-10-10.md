# VPS + CDN ایرانی — وضعیت واقعی v10.1

تاریخ: ۲۰۲۶-۱۰-۱۰. این سند جایگزین ادعای قبلی «VPS ایرانی + SNI اسنپ = نت ملی آماده» است.

## پاسخ دقیق به سؤال کاربر

نصب نود روی VPS، سرور را روی اسنپ یا یک سایت ایرانی قرار نمی‌دهد. روش ایرانیِ مطرح‌شده در آموزش‌های قبلاً بررسی‌شدهٔ SpiderPanel، دامنهٔ خود کاربر روی CDN ایرانی با مبدا دارای اینترنت جهانی بود. مبدا می‌تواند یک سرویس خارجی مثل Railway یا VPS خارجی باشد؛ ایرانی‌بودن VPS شرط آن روش نیست.

مسیر موردنظر: گوشی → لبهٔ قابل‌دسترسی CDN ایرانی → مبدا متعلق به کاربر → اینترنت.

- آدرس اتصال می‌تواند دامنهٔ خود کاربر یا یک IP/نام روی لبهٔ سازگار همان CDN باشد. هم‌CDN بودن اسمی نیز به‌تنهایی سازگاری یک لبه با دامنهٔ ما را ثابت نمی‌کند.
- Host و SNI **واقعی** باید دامنهٔ سرویس خود کاربر بمانند.
- `fakeSni` و `spoofIp` یک قابلیت جداگانه در کلاینت سازگارند؛ نباید با تغییر SNI واقعی به `snapp.ir` اشتباه شوند.
- باید ارتباط CDN به مبدا خارجی همچنان برقرار باشد. این روش اتصال خارجی را هنگام قطع همهٔ مسیرها ایجاد نمی‌کند.
- هیچ ادعایی دربارهٔ CDN فعلی اسنپ یا دسترسی فعلی اپراتور کاربر از روی نام آن سایت نمی‌شود.

## آنچه دوباره از کد SpiderPanel بررسی شد

منابع اولیه:
- https://github.com/amirh00sain/SpiderPanel/blob/main/main.py#L2340-L2395
- https://github.com/amirh00sain/SpiderPanel/blob/main/main.py#L2540-L2775
- https://github.com/amirh00sain/SpiderPanel/blob/main/README.md

در `generate_user_config` آدرس اتصال از Host/SNI واقعی جداست. `_spoof_payload` این شیء را در پارامتر URI به نام `snispoofing` می‌گذارد:

```json
{"active":true,"fakeSni":"<decoy hostname>","spoofIp":"<literal IP>","targetPort":0}
```

این پارامتر را کلاینت باید پشتیبانی و اجرا کند. صرف تولید لینک یا واردکردن آن در v2rayNG معمولی اجرای Spoof را ثابت نمی‌کند. نسخه/سیستم‌عامل واقعی V2Box در این کار آزمایش نشده است. در کد بررسی‌شده، API خودکار ابرآروان یا نصب برنامه روی اسنپ وجود نداشت؛ بخش CDN ایرانی مربوط به دستورالعمل‌های آموزشی است، نه چنین قابلیتی در کد.

## آنچه در v10.1 واقعاً تغییر کرد

- بخش پولی جدا اکنون «VPS + CDN ایرانی» است؛ REALITY مستقیم از مسیر CDN جدا و پیش‌فرض misleading اسنپ حذف شد.
- فرم نصب مبدا WS+TLS پشت CDN: دامنهٔ خود کاربر، Address لبهٔ هم‌CDN، مسیر WS، کاربر انتخابی و خروجی اختیاری Spoof.
- Host/SNI واقعی روی دامنهٔ خود کاربر می‌مانند؛ اعتبارسنجی TLS خاموش نمی‌شود؛ ALPN برابر `http/1.1` است.
- خروجی معمولی و خروجی مخصوص کلاینت سازگار جدا هستند. `?type=v2box` پارامتر Spoof را در لینک خام نگه می‌دارد؛ اشتراک عادی آن را به کلاینت ناسازگار تحمیل نمی‌کند.
- کانفیگ فقط پس از تأیید **دستی و صریح خود کاربر** به اشتراک اضافه می‌شود. این تأیید، آزمایش خودکار یا تضمین نت ملی نیست. تأیید به URI دقیق و UUID نصب‌شده متصل است؛ تغییر مسیر آن را بی‌اعتبار می‌کند.
- کاربران دیگر اشتراک، UUID نصب‌نشده روی این نود دریافت نمی‌کنند.
- ایجنت systemd بعد از reboot برمی‌گردد. نصب اولیه وابسته به مخزن Debian/Ubuntu، GitHub و پنل است؛ پس از نصب، قطع ارتباط مدیریتی پنل به‌تنهایی Xray را نمی‌خواباند.
- خطای certbot/Xray به‌عنوان موفقیت گزارش نمی‌شود. قبل از فعال‌سازی، کانفیگ با خود Xray بررسی می‌شود؛ شکست شروع سرویس، پیکربندی قبلی را برمی‌گرداند. فقط پروفایل فعلی واقعاً فعال گزارش می‌شود.
- حذف ثبت نود با توقف سرویس یکی نیست؛ UI این تفاوت را می‌گوید و دکمهٔ توقف جداست.
- کلیدهای Xray 26.3.27 با خروجی `Password (PublicKey)` پشتیبانی شدند.
- مشکل زندهٔ Cloudflare 1010 برای `Python-urllib` پیدا شد؛ join/poll/report اکنون User-Agent مشخص `Omni-VPS-Agent/10.1` دارند.
- مهاجرت جداول VPS از bootstrap قدیمی مستقل شد؛ پنل ازقبل‌نصب‌شده دیگر به‌خاطر fast path جدول جدید را جا نمی‌اندازد.
- ورودی‌های API محدود، نقش مدیر لازم، join یک‌بارمصرف، تسک‌ها تک‌به‌تک و نتیجهٔ تسک ناموفق قابل مشاهده است.

## مرزهای روشن: چه چیزی هنوز انجام نشده

1. **هیچ VPS واقعی ثبت نشده است**: شمارش read-only در هر دو DB پس از استقرار = صفر.
2. **هیچ حساب یا دامنهٔ CDN واقعی وصل نشده است.** اتوماسیون API ارائه‌دهندهٔ CDN، تغییر NS و ایجاد DNS در این نسخه پیاده‌سازی نشده؛ فرم مبدا، CDN ازقبل‌آماده‌شده را فرض می‌کند. این قسمت از درخواست «همه‌چیز خودکار» هنوز باقی است، نه اینکه تنها با یک توکن فوراً انجام شود.
3. ACME واقعی برای دامنهٔ کاربر آزمایش نشده. HTTP پورت ۸۰ باید مستقیم یا از CDN برای challenge به مبدا برسد و HTTPS به ۴۴۳ مبدا با گواهی معتبر متصل شود.
4. مسیر ایران → CDN → مبدا از داخل ایران و هنگام محدودیت واقعی آزمایش نشده؛ تست خط کاربر معیار نهایی است.
5. این نسخه تک‌پروفایل/کاربر انتخابی روی هر نود است. همگام‌سازی پیوستهٔ کاربران و حسابداری سهمیه‌های پنل روی Xray خارج از این مرحله است.

## تفکیک مدرک‌ها

| آزمون | نتیجه و محدوده |
|---|---|
| URI/validation/اسکریپت سرو‌شده | پاس؛ جدایی Address/Host/SNI/fakeSni، TLS فعال، منع ورودی نامعتبر و سینتکس shell/Python |
| Python agent unit | ۸ تست؛ خطای گواهی، rollback، وضعیت غیرفعال، retry نتیجه، خروجی کلید Xray، User-Agent |
| API/D1 | runtime محلی Miniflare؛ احراز هویت، join یک‌بارمصرف، صف، گزارش مصنوعی، تأیید دستی، محدودیت UUID و مهاجرت DB قدیمی |
| مرورگر VPS/CDN | APIها mock؛ فرم، خروجی‌های جدا، تأیید صریح و عدم نمایش موفقیت جعلی؛ jsErrors=[] |
| Xray واقعی | باینری 26.3.27 با checksum؛ TLS با اعتبارسنجی گواهی و تبادل VLESS/HTTP فقط روی loopback؛ نه CDN و نه خط ایران |
| رگرسیون قدیمی | smoke ۱۵/۱۵؛ scanner deterministic ۱۸؛ مرورگر بدون خطا |
| زنده | صفحه و اسکریپت روی دو Worker، UA ایجنت پذیرفته، API بدون ورود ۴۰۱، join نامعتبر ۴۰۴؛ بدون نوشتن نود/گزارش جعلی در DB واقعی |
| اشتراک موجود | ۶۶ URI حفظ شده؛ هیچ مسیر پولی آزمایش‌نشده اضافه نشده |

تست v10 قبلی با insert/report مصنوعی در DB، **نصب روی VPS یا اتصال از داخل ایران نبود**. ادعای «کل زنجیره روی VPS واقعی کار می‌کند» پس گرفته شده است.
