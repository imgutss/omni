## 🤖 اتصال ربات (یک قدم دستی)

پنل هنوز به ربات «جفت» نشده تا آیدی خودت ثبت شود (توکن ربات آیدی چت ندارد). این کار را انجام بده:

1. در تلگرام به **@OmniAiGateBot** پیام بده.
2. این را بفرست:

```
/pair 212098
```

> کد بالا از پنل (`POST /api/bot/pair-code`) ساخته شده. اگر منقضی/استفاده شد، از پنل → بخش ربات کد تازه بگیر.

بعد از این، همه‌ی دستورات فعال می‌شوند:

```
/help                 راهنما
/list                 لیست کاربران + مصرف و روز باقی‌مانده
/new ali 50 30        ساخت کاربر «ali» با ۵۰ گیگ و ۳۰ روز
/link ali             ساب‌لینک + کانفیگ + دکمه‌ی دانلود
/reset ali            ریست حجم
/extend ali 30        تمدید ۳۰ روز
/toggle ali           فعال/غیرفعال
/del ali              حذف کاربر
/note ali متن         یادداشت روی کاربر
/stats                آمار کلی پنل
/scan                 اسکن آی‌پی تمیز
/ips                  آی‌پی‌های تمیز ذخیره‌شده
/ping [host]          سلامت سرویس
/panel                لینک پنل
```

اعلان خودکار می‌گیری وقتی کاربری به **۸۰٪ حجم**، **اتمام حجم** یا **۲ روز مانده به انقضا** برسد.

## 🎯 آی‌پی تمیز (کم‌پینگ و عبور از فیلتر)

Cloudflare اجازه نمی‌دهد ورکر با `connect()` به آی‌پی‌های خودش (مثل `104.16.0.0`) وصل شود؛ پس تست این آی‌پی‌ها **از دیتاسنتر بی‌فایده یا غیرممکن** است. Omni آن را درست انجام می‌دهد:

1. کاربر صفحه‌ی **`/status/<token>`** را باز می‌کند → دکمه‌ی **«تست آی‌پی‌ها روی دستگاه من»**.
   آی‌پی‌ها از مرورگر خودِ کاربر (همان شبکه‌ی ایران) تست و نتیجه در D1 ذخیره می‌شود.
2. هر کاربر می‌تواند ستاره (★) بزند: «این آی‌پی برای من خوب بود».
3. در `/api/diag/rank-ips` نتایج کاربران + پروب لبه با هم ادغام می‌شوند و **آی‌پی‌های تأییدشده‌ی کاربران**
   به‌طور خودکار در **ابتدای همه‌ی ساب‌لینک‌ها** قرار می‌گیرند (دامنه‌ی پنل همیشه به‌عنوان گزینه‌ی سالم بعدی می‌آید).

یعنی هر چه کاربران بیشتری از صفحه‌ی وضعیت تست بزنند، پنل «خودش» بهترین آی‌پی‌ها را برای همه انتخاب می‌کند.

### 🧩 کانفیگ‌ها چطور ساخته می‌شوند (الگوی پنل‌های کارکرده در ایران)

هر ساب ۳۰ کانفیگ دارد که **به ترتیب احتمال کار کردن در ایران** چیده شده‌اند و همه‌ی
کانفیگ‌ها روی **پورت ۴۴۳ با TLS** شروع می‌شوند (پورت ۸۰ و بقیه فقط در انتها، به‌عنوان شانس اضافه):

| # | گروه | آدرس کانفیگ | چرا |
|---|---|---|---|
| ۱ | 🌐 Domain | `cdn.jsdelivr.net` · `registry.npmjs.org` · `www.speedtest.net` | آی‌پی دامنه‌های پرترافیک روی کلودفلر که اپراتور بسته‌شان نکرده؛ SNI/Host همان دامنه‌ی خود پنل است |
| ۲ | 🌐 IPv6 | `[2606:4700:...]:443` | در بیشتر اپراتورهای ایران IPv6 فیلتر نیست و تمیزترین مسیر است |
| ۳ | 🌐 Clean | `آی‌پی:پورت`هایی که **با هندشیک واقعی VLESS جواب داده‌اند** | اسکنر `pool-scan` فقط این‌ها را نگه می‌دارد |
| ۴ | 🌐 IPv4 | آی‌پی‌های تأییدشده/سفارشی و دامنه‌ی خود پنل | گزینه‌ی مطمئن |
| ۵ | 🌐 Alt | پورت‌های ۲۰۵۳/۸۴۴۳/۲۰۸۷ روی بهترین آدرس‌ها | وقتی اپراتور ۴۴۳ را می‌بندد |

هر ردیف **دو کانفیگ** دارد: یکی VLESS و یکی Trojan (پس هر آدرس، هم با UUID و هم با پسورد کار می‌کند).

⭐ **فرگمنت به‌صورت پیش‌فرض خاموش است** (`بدون فرگمنت`) چون فرگمنت روی موبایل CPU می‌خورد و
سرعت/پینگ را بد می‌کند؛ فقط اگر اپراتورت عمیقاً DPI می‌زند، از تنظیمات → «پریست فرگمنت»
یکی از پریست‌های MCI/ایرانسل/مخابرات را روشن کن. `Mux` هم پیش‌فرض خاموش است.

**Mux/فرگمنت را فقط برای عبور از فیلتر روشن کن، نه برای سرعت.**

### 🔬 تستر دستگاه (صفحه‌ی وضعیت) — موتور یادگیری پینگ

در `/status/<token>` دکمه‌ی **«تست از روی دستگاه من»** چه کار می‌کند:

1. **دامنه‌ها و هاست پنل** را از مرورگر خود کاربر (شبکه‌ی واقعی، مثلاً همراه اول) می‌سنجد —
   با گواهی معتبر، پس نتیجه‌اش واقعی است.
2. **سرعت دانلود واقعی** را از خود ورکر می‌گیرد (`/api/diag/speed`) → عدد Mbps.
3. هر کاندیدی که جواب بدهد در D1 ذخیره می‌شود و از آن لحظه **بالای همه‌ی ساب‌لینک‌ها** می‌آید.

آی‌پی **خام** را مرورگر نمی‌تواند بسنجد (گواهی TLS و ترافیک مختلط جلوی آن را می‌گیرد) — برای
آی‌پی‌ها معیار، «پینگ واقعی» خودِ v2rayNG و دکمه‌ی **★** در همین صفحه است.

### 🎛 اسکنر پنل (یک مسیر، صادقانه)

- دکمه‌ی «شروع اسکن» دامنه/هاست را **از مرورگر تو** و آی‌پی‌ها را **از لبه‌ی کلودفلر** می‌سنجد و
  هر ردیف برچسب منبع دارد.
- دکمه‌ی «افزودن برترین‌ها» دامنه‌های سالم را در `address_domains` و آی‌پی‌ها را در `clean_ips`
  می‌نویسد؛ از اسکن بعدی، کانفیگ‌ها با همان ترتیب ساخته می‌شوند.

### 🤁 جفت‌های «دست‌دادن‌شده» (verified pairs) — چیزی که پینگ را نجات می‌دهد

کانفیگ با آی‌پی حدسی روی کاغذ سالم است، ولی در شبکه‌ی ایران به سوکت نمی‌رسد. پس Omni فقط به حرفِ لیست‌ها تکیه نمی‌کند:
اسکنر `tools/pool-scan.mjs` از داخل خود ورکر به هر `آی‌پی:پورت` یک **هندشیک واقعی VLESS** می‌زند و فقط
جفت‌هایی که واقعاً جواب می‌دهند را در `settings.verified_pairs` ذخیره می‌کند.
سپس `buildConfigs` این جفت‌ها را **اول همه‌ی ساب‌لینک‌ها** می‌چیند (تا ۴۵٪ سهم، بعد دامنه‌ی پنل که همیشه سالم است،
و در آخر آی‌پی‌های حدسی برای شانس بیشتر).

```
node tools/pool-scan.mjs --password <رمز ادمین> --c 10   # اسکن ۲۳ آی‌پی × ۶ پورت، ذخیره در D1
node tools/sub-verify.mjs --password <رمز ادمین> --who <کاربر> --c 2
                                             # همه‌ی کانفیگ‌های ساب زنده را با هندشیک واقعی می‌سنجد
```

اگر روزی پینگ افت کرد: همین دو دستور را بزن و به v2rayNG بگو «Update subscription» — کانفیگ‌های تأییدشده‌ی تازه جایگزین می‌شوند.

⚠️ **یک محدودیت ذاتی همه‌ی پنل‌های Worker-based:** مقصدهایی که خودشان پشت کلودفلر هستند (مثل `example.com` یا `cloudflare.com`)
از تونل رد نمی‌شوند، چون Cloudflare اجازه‌ی اتصال خروجی به آی‌پی‌هایش را نمی‌دهد. بقیه‌ی اینترنت (یوتیوب، اینستاگرام، X، تلگرام، ویکی‌پدیا و…) عادی کار می‌کند.

## 🛠 کارهای روزمره

| کار | دستور |
|---|---|
| انتشار نسخه‌ی جدید روی کلودفلر | `cd ~/omni && npm run deploy:auto` |
| پوش کد به گیت‌هاب | `npm run push:github` |
| تست کامل محلی (۸۰ بررسی + تونل واقعی) | `npm test` |
| تست زنده روی ورکر منتشرشده | `LIVE_ADMIN_PASS=Omni-lsElDCiu node test/live.mjs` |
| لاگ زنده‌ی ورکر | `npx wrangler tail --config wrangler.toml` |
| اجرای دستی نگهداری (پاک‌سازی لاگ/منقضی) | پنل → دیاگ → «اجرای نگهداری» |
| اسکن آی‌پی‌های سالم (هندشیک واقعی) | `npm run pool -- --password <رمز>` |
| بررسی اینکه یک دامنه می‌تواند آدرس کانفیگ باشد | `node tools/domain-check.mjs cdn.jsdelivr.net medium.com` |
| سنجش همه‌ی کانفیگ‌های یک ساب | `npm run verify -- --password <رمز> --who <کاربر>` |

کرون هر **۵ دقیقه**: پولینگ ربات (در نبود وب‌هوک)، هشدارهای مصرف/انقضا، چرخش خودکار توکن (اگر روشن باشد)، نظافت لاگ‌ها.
