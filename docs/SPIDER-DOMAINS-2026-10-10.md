# دامنه‌های موجود کاربر — ۲۰۲۶-۱۰-۱۰

> به‌روزرسانی: توکن جدید دریافت و دسترسی DNS هر دو دامنه تأیید شد. دیگر از کاربر توکن CF یا نام دامنه درخواست نشود. هیچ رکوردی تغییر نکرد؛ گام بعد دسترسی/بررسی پلن CDN ایرانی است. SPIDER-DNS-ACCESS-2026-10-10.md را بخوانید.

کاربر با اسکرین‌شات گفت هر دو دامنه در حساب دیگری از Cloudflare هستند:
- drsarli.ir
- nnguts.dpdns.org

**دیگر از کاربر نپرسید آیا دامنه دارد و خرید دامنه توصیه نکنید.** اطلاعات دامنه دریافت شد؛ دسترسی حسابِ کنترل‌کنندهٔ آن هنوز فراهم نشده است.

## بررسی واقعی و فقط خواندنی
DNS عمومی هر دو نام به nameserverهای Cloudflare می‌رسد. drsarli.ir دارای Aهای پراکسی Cloudflare است؛ nnguts.dpdns.org هم A موجود دارد. پس نباید فرض شود ریشهٔ هیچ‌کدام خالی یا بلااستفاده است.
نام پیشنهادیِ مجزای آزمایش spider-test.nnguts.dpdns.org در زمان بررسی NXDOMAIN داد؛ این هنوز مجوز یا اقدام ساخت رکورد نیست و قبل از نوشتن باید با API و رکوردهای حساب واقعی دوباره چک شود.
با توکن فعلی، GET zones با فیلتر نامِ هر دامنه و **بدون فیلتر account.id قبلی** موفق بود ولی صفر zone نشان داد. بنابراین با اعتبارنامهٔ موجود به این دو zone دسترسی نداریم؛ پاسخ قبلیِ «دامنه یافت نشد» مربوط به محدودهٔ دسترسی بود، نه نبودن دامنه‌های کاربر.
Cloudflare connector یک بار بررسی شد و unsupported بود. API رسمی همچنان با توکن محدودِ خود کاربر قابل استفاده است؛ discovery آن connector تکرار نشود.

## قدم انسانی بعدی — فقط دسترسی محدود به یک دامنه
در همان حساب کنترل‌کنندهٔ nnguts.dpdns.org:
My Profile → API Tokens → Create Token → Edit zone DNS / Use template
Permissions:
- Zone / DNS / Edit
- Zone / Zone / Read
Zone Resources:
- Include / Specific zone / nnguts.dpdns.org
Global API Key، رمز ورود، All zones یا دسترسی کلی حساب لازم نیست.

توکن DNS این حساب باید در فایل خصوصی **جدا از CF_API_TOKEN فعلیِ Workerها** ذخیره شود؛ overwrite کردن اعتبارنامهٔ Omni/Nova می‌تواند استقرار و repair آن‌ها را خراب کند. توکن در Git، لاگ عمومی یا Drive منتشر نشود.

## محدودیت و حفاظت
هیچ رکورد DNS، nameserver، وضعیت proxy، دامنه، حساب یا پلنی تغییر نکرد. دامنه‌ها بین حساب‌ها منتقل نشوند؛ drsarli.ir و رکوردهای موجود nnguts دست‌نخورده بمانند.
هدف، بررسی امکان یک زیردامنهٔ تازه برای مسیر CDN ایرانی است. امکان و شرایط پلن CDN/روش اتصال آن باید پیش از فعال‌سازی نهایی بررسی شود؛ API token کلودفلر به معنی داشتن حساب/دسترسی CDN ایرانی نیست.
خود SpiderPanel هنوز نصب نشده، CDN ایرانی متصل نیست، محدودیت AUP ریلوی همچنان حل نشده، و هیچ کانفیگ نت ملی تأییدشده‌ای نداریم. اول رایگان و سپس تصمیم دربارهٔ هزینه پابرجاست.
تست مستقیم قبلی Railway بازنشسته و deployment آن حذف شده است؛ دوباره ایجاد نشود.
